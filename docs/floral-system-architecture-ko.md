# eFLOWER 기반 꽃 기관·개화 시스템

Floraxis의 꽃 생성 경로는 다음 네 층으로 나뉜다.

```text
eFLOWER식 종별 형질
  → 꽃 기관 그래프
  → 기관별 파라메트릭 표면과 반복 배치
  → 기관별 생장·개화 스케줄
```

이 분리는 Helios와 OpenAlea가 사용하는 핵심 원칙을 웹 실시간 렌더러에 맞게 옮긴 것이다. 식물의 위상, 기관 형상, 생장 법칙을 한 함수에 섞지 않기 때문에 같은 꽃 기관 그래프에 다른 꽃잎 표면이나 개화 시간표를 적용할 수 있다.

## 1. eFLOWER 형질을 렌더 데이터로 바꾸는 방법

eFLOWER 연구는 792종에서 21개 꽃 형질을 정리해 속씨식물 조상꽃을 재구성했다. Floraxis는 이 중 화면 생성에 직접 영향을 주는 다음 항목을 사용한다.

- 꽃의 방사대칭/좌우대칭
- 화피의 꽃받침·꽃잎 분화 여부
- 나선/윤생 배열, 윤 수, 수성, 기관 융합
- 수술의 수, 배열, 윤 수, 꽃실 연결 방식, 꽃밥 방향
- 심피 수, 심피 융합, 심피당 밑씨 수
- 상위/하위/화탁 매입 자방

원 데이터의 범주형 형질과 렌더 프리셋의 계측값을 구분한다. 예를 들어 다마스크 겹장미의 42개 꽃잎은 재배형의 화면상 기관 수이고, 5수성은 장미과의 기본 기관 조직을 설명하는 형질이다. 해바라기·수국·등나무는 단일 꽃이 아니라 꽃차례이므로 `꽃머리 전체`와 `소화당` 수를 기관 그래프의 `scope`로 구분한다.

참고 자료:

- [The ancestral flower of angiosperms and its early diversification](https://www.nature.com/articles/ncomms16047)
- [Open Traits eFLOWER 형질 사전과 데이터 라이선스](https://opentraits.org/datasets/e-flower)
- [eFLOWER PROTEUS 데이터베이스 설명](https://eflower.myspecies.info/proteus)

## 2. 꽃 기관 그래프

`src/flower/floral-organ-graph.ts`는 프리셋을 부모-자식 그래프로 정규화한다. 각 노드는 기관 종류, 부모, 개수, 윤, 나선/윤생/군집 배열, 융합 상태, 수성과 적용 범위를 가진다.

- 튤립·백합: 화피 2윤 × 3개와 수술 2윤 × 3개
- 장미·연꽃: 황금각을 쓰는 연속 나선 기관 순서
- 해바라기: 화탁 아래 설상화와 통상화, 통상화당 수술·심피
- 수국: 장식화와 가임화, 장식화당 확대 꽃받침조각
- 등나무: 총상화서 아래 기판 1, 익판 2, 용골판 2

윤생 기관은 매 윤을 반 칸 회전해 교대로 배치하고, 나선 기관은 전역 시작 순서에 황금각을 적용한다. 같은 함수가 한 송이 렌더러와 꽃밭 인스턴스 렌더러에서 함께 사용된다.

OpenAlea의 MTG(Multi-scale Tree Graph)는 서로 다른 축척의 식물 위상을 공유하는 구조다. Floraxis의 그래프는 꽃머리 범위에 한정한 가벼운 MTG식 표현이며 OpenAlea 파일 호환 구현은 아니다.

- [OpenAlea 모델링 패키지: MTG, L-Py, PlantGL](https://openalea.readthedocs.io/en/latest/packages/modelling.html)

## 3. 유리 베지어/NURBS 꽃잎

각 꽃잎은 4×4 제어점과 가중치를 가진 유리 3차 베지어 표면으로 생성한다. 이는 매듭 벡터가 양끝에서 고정된 단일 스팬 NURBS 패치와 동등하다. 별도 OBJ 꽃잎 에셋은 필요하지 않다.

종별 표면 파라미터는 다음을 제어한다.

- 기부·중간·어깨·끝 너비
- 어깨 위치와 중륵 아치
- 횡방향 컵 곡률
- 좌우 비대칭
- 내부 제어점의 유리 가중치

표면에서 얻은 기본 좌표 위에 봉오리 말림, 기부 팽창, 가장자리 초과 생장, 중륵 접힘, 끝 후굴, 장미 중심의 단측 말림을 순서대로 합성한다. 따라서 종별 기본 형태를 바꾸어도 기존 개화 모프와 중심 말림은 마지막 변형 단계로 남는다. 실제 얇은 셸 두께, 옆면, 앞·뒷면 노멀과 잎맥 노멀맵도 유지된다.

## 4. Helios/OpenAlea식 기관 성장 스케줄

Helios의 PlantArchitecture는 종별 phytomer·기관 프로토타입과 phyllochron, 신장, 굵기 성장, 굴중성 같은 생장 파라미터를 분리한다. 다만 꽃 프로토타입은 보통 외부 OBJ와 열린/닫힌 상태에 의존한다. Floraxis는 꽃잎 프로토타입을 파라메트릭 표면으로 대체하고 다음 기관별 시간을 계산한다.

- 꽃머리·화탁: 봉오리 팽윤 구간
- 꽃받침: 꽃잎보다 먼저 이완
- 꽃잎·화피: 종별 개방 시작, 전개 기간, 시작 순서 지연
- 수술·심피: 별도의 생식기관 노출·성숙 구간
- 해바라기 통상화와 복합 꽃차례 소화: 공간 순서에 따른 추가 지연

그래프 노드는 정적 구조이고 성장 스케줄은 시간 함수이므로, 커스텀 프리셋에서 꽃잎 형상을 바꾸어도 기관 순서가 사라지지 않는다.

- [Helios PlantArchitecture 문서](https://plantsimulationlab.github.io/Helios/_plant_architecture_doc.html)

## 5. 커스텀 프리셋 호환성

새 JSON에는 `floralSystem.schemaVersion = 1`과 `traits`, `petalSurface`가 저장된다. 이전 버전 JSON에 이 필드가 없으면 종 ID, 꽃차례 종류, 꽃잎 수와 모양에서 가장 가까운 기본 프로필을 복원한다. 모든 수치 입력은 렌더 안전 범위로 제한된다.

현재 구현은 기관 수준의 시각적 생장 모델이다. 세포 분열, 팽압, 물질수송, 온도 반응을 수치해석하는 생물역학 모델이나 eFLOWER 전체 데이터베이스의 자동 종 동정기는 아니다.
